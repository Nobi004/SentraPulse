# Security Policy

## Reporting a vulnerability

Please report security issues privately: open a GitHub issue titled
`[SECURITY]` with minimal reproduction details, or contact the repository
maintainers directly. Do not disclose vulnerabilities publicly until a fix
is available.

## Ground rules

- Never post secrets (API keys, connection strings, tokens) in issues,
  pull requests, or logs. The application never logs secrets by design —
  please keep it that way.
- Do not probe or overload running demo deployments.

## Supported versions

Only the current `main` branch is supported with security updates. There
are no long-term-support releases at this stage.
